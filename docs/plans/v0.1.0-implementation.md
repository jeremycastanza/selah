# Selah v0.1.0 Implementation Plan

## Overview

Stand up Selah from an empty repo to a fully working Bible TUI with all 8 features from scope: clean reader interface, random verse, mouse interaction, bookmarks, splash screen, theme toggle, search, and Bible version toggling.

## Current State Analysis

The repo is a documentation skeleton — no `Cargo.toml`, no `src/`, no `.gitignore`, no data files. All specs are written in `docs/specs/`. Two source forks exist at `forks/christ-cli` (Rust) and `forks/bible-tui` (JavaScript) with directly portable code for books metadata, themes, and CI workflow.

### Key Discoveries:

- `forks/christ-cli/src/data/books.rs` — 66 books with metadata, directly portable
- `forks/christ-cli/src/ui/theme.rs` — 5 themes with full color palettes, directly portable
- `forks/christ-cli/.github/workflows/release.yml` — Multi-platform CI, adaptable for Selah
- `forks/christ-cli/Cargo.toml` — Release profile with `opt-level = "z"`, `lto = true`, `strip = true`
- christ-cli uses tokio/reqwest (async HTTP) — Selah drops both; everything is sync and offline
- bible-tui's 4-panel proportions (25/17/58) confirmed in `utils/ui.js`

## Desired End State

Running `cargo run` launches a TUI with:
- Animated splash screen (skippable, full-color ASCII art)
- 4-panel Bible reader (Books | Chapters+Verses | Scripture)
- Keyboard (vim-style) and mouse navigation
- Full-text search via `/` key
- Bookmarks via `b`/`B` keys, persisted to JSON
- Theme cycling via `t` key (5 themes)
- Translation picker via `v` key (KJV only in v1, graceful for others)
- Session persistence (position, theme, translation restored on relaunch)
- `selah random` CLI subcommand

Verification: `cargo build --release` produces a single ~8-9 MB binary. `cargo test` passes. `cargo clippy -- -D warnings` clean. `cargo fmt --check` clean.

## What We're NOT Doing

- No extra translations beyond KJV (v1 bundles KJV only; `extra-translations` feature flag is defined but not populated)
- No Windows support
- No async runtime (no tokio)
- No network requests
- No cloud sync
- No web interface
- No custom user themes (5 built-in only)
- No CI/CD in this plan (Phase 9 is a follow-up; the workflow template exists in christ-cli for when we're ready)

## Implementation Approach

Bottom-up: scaffold → data → core loop → features layered on top. Each phase produces a compilable, testable checkpoint.

**File**: `src/app.rs`

```rust

    Banner(BannerState),
    Browser(BrowserState),
}

    pub mode: AppMode,
    pub theme_name: ThemeName,
    pub bookmarks: Vec<BookmarkEntry>,
```

Main run loop:
1. Initialize terminal (crossterm raw mode, alternate screen, mouse capture)
2. Load session state and bookmarks from disk
3. Open SQLite connection
4. Enter event loop: poll events → dispatch → draw → repeat
5. On quit: save session, restore terminal

#### 4. Event loop

**File**: `src/app.rs` (continued)

```rust
loop {
    terminal.draw(|frame| self.draw(frame))?;
    if event::poll(tick_rate)? {
        match event::read()? {
            Event::Key(key) if key.kind == KeyEventKind::Press => self.handle_key(key.code),
            Event::Mouse(mouse) => self.handle_mouse(mouse),
            _ => {}
        }
    }
    if self.should_quit { break; }
    if matches!(self.mode, AppMode::Banner(ref s) if s.done) {
        self.mode = AppMode::Browser(BrowserState::new(&self.db, &session));
    }
}
```

Tick rate: 16ms in Banner mode, 50ms in Browser mode.

## Phase 4: Reader (F1)

### Overview

Implement the 4-panel browser layout with keyboard navigation and session restore. After this phase, users can browse all 66 books and read chapters.

### Changes Required:

#### 1. BrowserState

**File**: `src/ui/browser.rs`

Full `BrowserState` struct per F1 spec:
- `active_panel: Panel` enum (Books, Chapters, Verses, Scripture)
- `book_list`, `chapter_list`, `verse_list`: ratatui `ListState`
- `scripture_scroll: u16`
- `selected_book_idx`, `selected_chapter`, `selected_verse`
- `current_chapter: Option<Chapter>`
- `translation: String`
- `overlay: Option<OverlayKind>`
- Panel rects for mouse hit-testing (initially `Rect::default()`)
- `status_flash: Option<(String, Instant)>`

#### 2. Panel rendering

**File**: `src/ui/browser.rs`

`render_browser(frame, area, state, quit_pending, theme)`:
1. Outer vertical split: browser area + status bar (1 row)
2. Browser horizontal split: 25% | 17% | 58%
3. Middle column vertical split: 50/50 Chapters | Verses
4. Books panel: `List` of 66 books from `BOOKS` array
5. Chapters panel: `List` of chapter numbers for selected book
6. Verses panel: `List` of verse numbers for selected chapter
7. Scripture panel: `Paragraph` with word-wrap, scrollable
8. Active panel indicated by `border_active` color and `[*]` label
9. Status bar: keybinding hints | translation | theme name
10. Store computed rects back into `state` for mouse hit-testing

#### 3. Keyboard navigation

**File**: `src/app.rs`

Key dispatch in Browser mode (no overlay):
- `h/←`: move focus left (`Panel::prev()`)
- `l/→/Enter`: move focus right (`Panel::next()`), trigger chapter load when entering Scripture
- `j/↓`: move selection down in active list panel
- `k/↑`: move selection up in active list panel
- `q`: double-press quit (first sets `quit_pending`, second sets `should_quit`)

Chapter load: when a chapter is selected and confirmed, query `db::get_chapter()` and populate `current_chapter`.

#### 4. Session restore

On `BrowserState::new()`, apply saved `SessionState`:
- Set `selected_book_idx`, `selected_chapter`, `active_panel`, `scripture_scroll`
- Load the saved chapter from SQLite

On quit, build `SessionState` from current `BrowserState` and call `session::save()`.

## Testing Strategy

### Unit Tests:
- Bible data: book count, book names, chapter counts
- SQLite queries: get_chapter, get_verse, search, random_verse
- State machines: BannerState tick transitions, Panel cycling, ThemeName cycling
- Persistence: SessionState serde round-trip, BookmarkEntry serde round-trip, bookmark deduplication
- Hit testing: boundary coordinate checks

### Integration Tests:
- Full app lifecycle: init → load session → render one frame → save session → quit
- Database embedding: verify `include_bytes!` loads a valid SQLite database

### Manual Testing Steps:
1. Launch app — splash screen plays, transitions to reader
2. Navigate all 66 books via keyboard
3. Click panels and scroll with mouse
4. Search for "love" — verify results and navigation
5. Bookmark a verse, quit, relaunch — verify bookmark persists
6. Cycle through all 5 themes
7. Open translation picker — verify KJV selectable, others grayed
8. Press `r` for random verse multiple times
9. `selah random` from CLI
10. `selah --no-banner` skips splash
11. Resize terminal at various sizes

## Performance Considerations

- SQLite in-memory: all queries sub-millisecond for KJV (~31k verses)
- No async runtime: zero overhead from tokio
- Theme resolved at render time: no reallocation on theme switch
- Banner tick at 16ms (60fps); Browser tick at 50ms (20fps) — adequate for both animation smoothness and input responsiveness
- Binary size ~8-9 MB with KJV embedded and release profile optimizations (FTS5 index built at runtime to save ~2.8 MB on disk)
